# 开发基线确认记录

Q1–Q46已确认，最后一轮用户回复“全部确认”。设计与组件复用策略现作为开发基线；具体依赖锁版与候选门禁仍需实验。这里记录的是共同理解，不是已经上线或实测通过的承诺。

## 1. 当前共同理解

1. 交付一个单企业私有化、可视化创作与统一入口调用的 Agent 平台；首周销售分析只是验收切片。
2. Go 控制业务状态与授权，Python 执行整张 LangGraph 图，DeepAgents 仅运行自主节点；Vue Flow 只处理编辑表示。
3. 使用 PostgreSQL durable jobs；Redis 不存唯一任务真相。个人记忆先按明确确认的数据库模型实现，不强制部署 Mem0。
4. 固定版本制品包含图、工具/模型配置、编译器及worker环境。旧运行恢复时保留旧制品。
5. 首版失联先挂起，证明旧执行单元退出后恢复；自动接管需要另外通过 checkpoint 原子围栏实验。
6. 脚本默认无自由出网/原始密钥，外部能力经代理；危险操作需要具体参数审批。首周只用预置工具。
7. 首版限定结构化分支/汇合，不开放任意跨区边、动态map或共享全局变量。
8. 默认配额、保留期限与性能目标按 OPERATIONS，可通过配置调整；未经测试不作为能力声明。
9. 离线微调必须先有强基线和真实错误；即使最终不部署LoRA，可信的无收益结论也构成实验交付。
10. 完整首版分阶段，第一周不把所有需求同时做完。

## 2. 不满足时缩小或停止

| 可推翻条件 | 对应动作 |
|---|---|
| LangGraph/DeepAgents固定锁版无法完成审批/旧图恢复 | 暂停多Agent/复杂图，先解决集成，不改成无恢复承诺的“成功” |
| gVisor/网络/构建隔离无法通过负例 | 只开放管理员预置工具，关闭任意上传 |
| 业务人员无法独立创建/修改一个真实应用 | 收窄画布与模板、实测交互，再扩节点 |
| unknown外部写被自动重试或批准可被换参数复用 | 阻断发布，修复协议 |
| 现有工具完成同任务更省事且用户无持续使用需求 | 转为上游贡献/插件或停止平台扩大 |
| 微调不优于强提示/检索且引入延迟/维护成本 | 保留实验报告，不上线adapter |

## 3. v0.2新增策略（已确认）

- **Q45**：采用PG记忆基线＋Mem0优先对照，确认/收益/完整删除门禁通过后才正式接入；不更改已经确认的个人记忆语义。
- **Q46**：采用确定性测试＋统一TaskRunner＋一个通用质量适配器（优先验证DeepEval），Ragas专项按需；不把全部框架或benchmark工作台列为首版必需。

两项均已由用户确认。完整技术细节、证据和未覆盖范围见 [OPEN-SOURCE-REUSE.md](OPEN-SOURCE-REUSE.md) 和 [TESTING-AND-DATASETS.md](TESTING-AND-DATASETS.md)。候选保持门禁状态；确认实验/接入策略不等于组件已通过实验或已安装。无需重新确认这些已有决定。

## 4. 尚需的真实用户证据

至少找到一个愿意重复使用的业务场景，记录频率、现有绕过、可接受的数据去向和创建/维护成本。当前只有产品选择与工程方案，没有安装/留存/付费或 Stars 的证据。首次可用演示应以任务完成观察为主，而非只征求“这个平台看起来不错”。

## 5. 实施授权边界

设计访谈的共同理解确认条件已满足。接手者不需要安装原会话使用的本机技能或读取旧聊天；收到开发指示即可按HANDOFF/任务图进入P0，不再索要相同范围的确认。只有实验推翻选型、需要改变已确认范围或出现新的重大取舍时，才重新讨论。本次文档审阅没有启动平台实现。
