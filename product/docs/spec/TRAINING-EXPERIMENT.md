## 建议调查的首个训练目标

平台应用目录持续变化，因此不把固定 Agent ID 当作永久分类标签。候选实验：给定用户需求、必要的任务上下文及运行时获授权候选应用用途说明，输出选择候选、需要澄清或无适合候选的结构化决策。实际是否值得训练，须先取得提示与规则基线的错误证据。

模型只能建议当前候选中的处理者，服务端仍验证候选成员身份、发布状态与使用权限。微调不授予权限，不替代候选检索、发布审核、输入校验或运行可靠性。

## 数据与实验要求

- 首个实验优先使用自建或公开、人工确认的样本。训练样本应含候选用途说明，不能只训练应用名称映射。
- 包含近似用途的难例、缺必要信息、无适合候选、复合需求和上下文追问。
- 按任务模板/应用家族划分训练、开发、测试，保留未参与调试的新应用用途测试；避免只随机拆分同一问法的改写。
- 测试候选排序变化，检查位置偏好与记忆固定目录造成的假提升。
- 至少比较：规则/检索加提示基线、相同基模的提示方案、相同基模加 LoRA。输入、候选检索和后处理条件一致。
- 记录正确路由、澄清/拒识、结构化输出有效性、越权建议被拦截、成本与延迟；再验证对端到端任务成功的影响。
- 训练 loss 下降不作为任务收益结论。没有留出集收益、出现严重退化或强提示基线已足够时，可停止微调。

## 产物与接入建议

每次实验记录不可变 manifest：基模与 revision、数据与 split/hash、训练代码 commit、配置与 seed、adapter/hash、推理模板、评测输入和结果、资源与耗时。输出目录按实验区分，避免覆盖既有产物。

经评测后，由管理员登记确定模型/adapter 版本与服务端点，验证结构化输出和工具调用契约，再决定是否启用。模型服务别名不能替代发布版的确定版本引用。

训练运行在独立的受控实验环境，不放进在线 API 进程或普通用户脚本沙箱。硬件规格和推理部署方案需在模型/数据量确定后验证。首版训练交付是离线实验与管理员模型登记；在线训练工作台、DPO/强化学习后续按实际数据与需求展开。

## 最小实验执行规格

先冻结候选检索和100例留出集，再分析基线错误；只有错误可通过训练目标解释才生成训练数据。训练/验证/测试按任务与应用家族隔离，同一需求的改写不得跨集合。每个样本包含 query、必要context、获授权candidate cards和结构化决策；记录人工来源/标签理由和许可证。人工标注预算足够也不能用数量掩盖模板泄漏。

模型选择门禁：可合法使用/分发adapter、支持所需语言与结构化输出、在可用硬件上完成一轮、能作为在线路由候选；在此之前不写一个未经验证的权重名称作为既定依赖。选定后固定模型仓库revision与tokenizer/template。推荐初始 LoRA rank=8、learning_rate=1e-4、epochs=2、seeds=17/29/43；实际batch/accumulation/精度按显存探针固定，报告effective batch及所有改变。以上是起点，不保证最优；不进行无边界超参搜索。

运行命令形态为 `llamafactory-cli train <本次已填完整配置.yaml>`；配置必须包含唯一output_dir、dataset revision、eval split、template、finetuning_type=lora和明确的保存策略，不能照抄会覆盖旧产物的示例。文档目前没有实际权重/训练配置，不把该命令写成可立即执行的实验。

指标逐例配对：正确选择/合理澄清/无匹配、错误自动选择、结构输出失败、被服务端拦截越权建议；另报候选召回率，区分检索失败与模型决策失败。相同测试输入下比较强提示与LoRA，三seed报告范围，并以配对bootstrap估计改善的不确定性。新增应用家族和候选乱序是未参与调参验证；不能训练后再选择有利子集汇报。

建议继续条件：留出任务错误有可重复下降，未见应用/拒识无明显退化，端到端成本/延迟符合目标用户容忍范围。若改进仅来自训练集目录记忆、对照提示调整后消失或置信区间仍不清晰，应缩小结论或补样本，不称已提升。无收益时保留可复现实验，不向在线系统强塞模型。
