# 实施任务、依赖与完成条件

按每日约8小时、首周约56小时规划纵向切片目标，实际取决于P0结果，不能将估时当保证。完整首版保留全部已确认范围，按门禁推进。**v0.3执行依赖以IMPLEMENTATION-ORDER和contracts/task-graph.json为准；下表F编号是功能分组，不再作为未拆分的大任务依赖。**

## 1. 开发前阻断实验 P0

组件复用以 [OPEN-SOURCE-REUSE.md](OPEN-SOURCE-REUSE.md) 状态为准，候选未通过探针不进入默认生产依赖。研究源码不是要求将全部上游项目作为fork维护。

| ID | 产物 | 检查与停止条件 |
|---|---|---|
| P0-1 | 源码/依赖/镜像锁、许可证清单 | DeepAgents/LangChain/LangGraph/checkpointer 能一起安装并调用；冲突未解决不开始大面积业务开发 |
| P0-2 | 最小图 start→interrupt→resume 的持久化实验 | 重启、旧版本、不同用户定位 ID；恢复不得加载新图/越权 |
| P0-3 | Linux OpenSandbox/runsc 策略与逃逸负例 | 默认无出网/宿主/凭据，超限可终止；失败则关闭任意脚本上传 |
| P0-4 | 受监督进程+领取/取消/失联保守恢复 | 心跳超时不双跑，确认退出才恢复；未知外部写不重发 |
| P0-5 | DSL golden corpus 与 Schema/Go/Python 对齐 | 线性、条件、并行、嵌套、skipped 与非法跨区；不通过的节点不开放发布 |

这些是小实验，可在最终平台代码框架建立前运行；所有结果以命令、日志、版本和 `passed/failed/not_run` 保存。自动 checkpoint 围栏为可选增强，不是首周必须自研的大模块。

## 2. 第一周建议切片

| 日期 | 工作与预算 | 可检查交付 |

## 4. v0.2追加的组件探针（按对应阶段执行，不全部挤进首周）

| ID | 挂接任务 | 对照/输出 | 失败动作 |
|---|---|---|---|
| C01 | F04/UI | VueFlow+Element Plus节点面板、变量/导出敏感字段负例 | 调整面板，不改执行语义迁就UI |
| C02 | F06 | 受控模型适配、tool-call/stream/cancel/usage；stub实际调用次数 | 禁用不兼容模型，解决隐藏多层重试 |
| C03 | F10 | 普通PDF reader vs Docling Native，出处/错误/依赖；分块基线 vs SentenceSplitter | 无收益则保留轻量基线，不扩OCR承诺 |
| C04 | F09/F11 | PG基线 vs Mem0确认后写、召回/费用/所有副本删除 | 未满足治理/收益不正式采用 |
| C05 | F13 | 同录制结果给hard checker与DeepEval候选；外发/费用记录 | 换本地接口/适配器或减少指标 |
| C06 | F13 | 外部task+环境+checker导入、空验拒绝、攻击成功含义映射 | 拒绝不完整任务，不报告假分数 |
| C07 | F15 | S3预签名、匿名拒绝、路径/删除/备份；自部署时SeaweedFS对照 | 使用已有合格S3或更换实现 |

上述探针均not_run。MCP/LiteLLM等后续能力不凭仓库已clone而升级为首版需求。TaskRunner与业务hard checker优先于部署多个评测管理服务。

| 数据工程 | 记忆确认、引用溯源、删除传播 | 无授权使用所有用户数据训练 |
| 模型优化 | 可复现SFT、同基模对照、泛化/退化分析 | 训练loss下降即业务提升 |

项目完成后的简历指标只能从真实结果填写；Stars、企业用户、并发与效果均不得预填。
