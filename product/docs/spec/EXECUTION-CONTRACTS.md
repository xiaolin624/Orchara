# 执行契约草稿

状态：本文保留产品语义摘要；现行执行协议见 EXECUTION、STATE-MACHINES、API 和 DATA-MODEL，尚未实跑验证。

## 请求与运行

1. 用户通过 Web 对话或附件提交一项需求，先形成平台请求。
2. 路由只考虑该用户有权使用的已发布应用；歧义由用户选择，信息不足先澄清。
3. 补充澄清信息属于原请求，不因每一条消息启动独立任务。
4. 匹配并补齐必要信息后，创建绑定发布版本的主应用运行。
5. 同一平台会话可以跨运行切换应用，展示处理者；只交接必要信息，不默认互通所有内部数据。

## 工作流与协作

外层画布为有向无环图，允许条件分支和并行汇合；Agent 节点内部允许受预算控制的自主迭代。主应用对任务结果负责，可以显式调用固定版本、获授权的子应用；依赖不得形成循环，调用有层数和次数限制。

同一会话的串行约束控制用户顶层任务；内部子任务的并行数与资源仍需独立配额。这是多 Agent 复用后需要在详细执行规范中落实的层级区分，实际锁、调度、状态和预算参数尚未设计完成。

## 发布制品

应用和脚本发布版本固定，运行不追随作者后续修改。脚本附带输入输出说明和依赖声明，调试/发布前准备固定运行环境，正式执行不临时联网安装。

检查点不等于发布制品。静态核查显示 LangGraph 恢复使用可用图代码，因此平台必须有明确的运行到不可变工作流/脚本制品的绑定与加载机制。详见 research/workflow-persistence-and-resume.md；尚未运行恢复验证。

## 资料与记忆

应用共享不自动共享使用者内容。组织资料经授权检索并提供出处；个人记忆按用户与应用隔离，明确请求或确认后保存，允许查看、修改和删除。任务附件不能未经许可进入组织知识库。

## 未决契约

节点变量类型；子应用输入输出/权限/预算；审批有效期和具体状态；取消与超时；重试次数与模型降级；并行分支失败及汇合；脚本文件协议与构建；知识文档更新/删除；路由与交接策略；保留、审计和恢复。

## 审批与故障原则（已确认）

发布审核和运行审批不同。对外发送、修改企业系统等受控高影响操作在执行前展示目标及参数，由有权限的发起者确认。批准与具体参数绑定，不能替代授权；批准后继续原运行，拒绝或审批过期终止本次运行。读资料及纯本地统计不默认逐次审批。

读取与纯计算允许有限重试，外部写入结果不明时应暂停核对而非盲目重发。恢复时复用已确认完成的步骤结果，保留错误及部分产物。该策略不表示检查点或本地记录可以保证第三方写入 exactly-once；还须通过外部工具契约、幂等键或权威核对接口处理边界。

任意上传脚本的行为不能仅靠提示词或声明来证明，受控外部操作的执行通道、凭据和网络权限必须在技术方案中落实；该点属于尚需具体化的实现约束。
