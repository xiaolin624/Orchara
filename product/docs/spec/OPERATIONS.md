# 部署与运维实施说明

这是拓扑和 runbook 规格，当前没有应用镜像/可执行 Compose 文件，不能执行一条命令就得到平台。部署实现任务见 DEVELOPMENT-PLAN。

## 1. 服务与环境

平台 Linux 主机：反向代理/TLS、Web 静态文件、Go API/维护任务、Python worker supervisor、PostgreSQL、Redis、S3 服务端点。脚本 Linux 主机：OpenSandbox、gVisor、隔离构建与执行；训练使用独立环境。正式环境凭据分别分发，不把数据库暴露给脚本网络。

开发可用 Windows + 远程 Linux 执行宿主；Windows/WSL 下 runsc 兼容性没有验证，不作为正式验收。首轮平台实验建议 8 vCPU/16GB 起步，脚本宿主独立；这是资源起点，不是20并发容量承诺。GPU 按离线训练选定基模再估算，不预购固定卡型。

配置至少包括：数据库/Redis/S3 内网地址、cookie/令牌密钥引用、worker mTLS、模型允许列表、脚本网络策略、配额、保留期。生产启动对 host 网络、明文公网数据库、开发密钥、未配置 gVisor 等危险配置 fail closed。

## 2. 依赖锁版和发布

生产依赖、可选服务、CI工具与训练环境分别锁版。源码参考平台不进入Compose；DeepEval/Ragas/Promptfoo、外部任务环境、Playwright/k6/Toxiproxy默认不随线上Agent常驻。Mem0/解析器如获选，记录其SQLite/模型文件/缓存等副本与清理责任。参考HEAD可能为dev/next，实际使用稳定发行版需重新锁定与兼容测试。

P0 获取官方源码/发行包并记录 commit；生成 `go.sum`、前端 lockfile、Python lock、镜像 digest 与 SBOM。研究 commit 是阅读锚点，不自动等于所用发行版；实际安装解析结果写 `versions.lock.json`。检查 DeepAgents 的 LangChain 最低版本，运行工具列表/interrupt/异步 checkpointer 兼容测试后才冻结。

构建镜像不使用 `latest`。部署先备份、迁移预检、执行单一迁移任务、启动兼容新 worker、健康检查和冒烟；最后更新流量。旧制品在恢复窗口保留；新 worker 不接不兼容旧任务，回滚不是降级数据库 Schema 的随意反向执行。

## 3. 初始参数（推荐，可配置）

| 参数 | 默认值 | 理由/边界 |
|---|---|---|
| 顶层活跃 Run | 全局20、每用户2、每会话1 | 容量目标；不是模型并行数 |
| 同时执行单元 | 验收顶层20、子任务8；开发可降为8/4 | 等待释放槽；资源不足应标未通过容量验收 |
| 模型/脚本并行 | 日常8/4；替身容量profile至少20/按负载配置 | 独立限流，真实模型另受供应商限额 |
| 子调用 | 深度3、总数12、每父并行3 | 防扇出与递归，发布校验无环 |
| Agent 轮数 | 12轮 | 超限停止，不能无限“继续思考” |
| Run 截止时间 | 15分钟活跃执行；审批等待24h | 等待不烧算力；超期明确失败 |
| job 心跳/租约 | 5s / 30s | 超期进入 recovery_pending，不自动双跑 |
| 脚本资源 | 1CPU、512MiB、60s、输出20MiB | 应用可申请更高，经管理员准入 |
| 附件/上传 | 每文件20MiB、每请求5个 | 实际解析另有限制，压缩后大小不足以判断 |
| 下载 URL | 60s | 敏感场景走代理即时鉴权 |
| 幂等请求键 | 24h | 外部 operation 回执更长保留 |
| 物理清理目标 | 逻辑删除后24h | 非完成事实，失败可观测告警 |
| 临时文件 / 事件 | 1天 / 7天 | 最终结果和正文按用户内容策略 |
| 备份 / 最小审计 | 30天 / 180天 | 用户/部署者可调整，法律需求另定 |

默认费用预算不写死某币种价格：管理员设置主/备模型价格版本，应用声明每 Run 最高预算，发布和运行预检。未配置预算不得启用可自主循环的共享 Agent。财务硬上限以供应商账户配额补充。

## 4. 备份和恢复

PostgreSQL 备份+WAL、对象存储版本/备份及不可变镜像清单共同构成恢复集；Redis 无需作为任务备份。推荐目标 RPO 15min、RTO 4h，仅在演练达到后才能对外宣称。

恢复到隔离环境 → 验证 DB/对象一致性和解密 → 回放删除账本/禁用已撤销 key → 停止所有旧 worker token → 标记非终态 recovery_pending → 按监督证明逐项恢复 → 核对未知远端操作 → 开放读取/执行。演练记录实际耗时与数据缺口，不只检查备份文件存在。

## 5. 运维手册

- worker 失联：保留任务，查 supervisor/container 与租约，禁止手工把 ready 改回去绕过死亡证明。
- 外部 unknown：查 operation ID/供应商回执；有证据再确认，不点“全部重试”。
- 数据库故障：停止新任务/副作用授权；不要在内存继续审批并稍后补写。
- Redis 故障：回退数据库轮询及保守限流，任务事实不丢；不能因为缓存不可用放开所有并发。
- 脚本宿主资源耗尽：停止新脚本，隔离异常沙箱，保留受控日志，平台 API 仍可读状态/发取消。
- 删除积压：告警 deletion_job age/失败数，下载/检索继续按 tombstone 拒绝。

指标标签避免 user_id/run_id 高基数；详情用受权日志/事件查询。监控 job age、recovery_pending、unknown 操作、审批等待、预算预留、PG连接、模型限流和正文清理延迟。
