## 决策树

- R1：产品方向已确认为企业内部 Agent 创作与运行平台，普通业务人员通过工作流画布创建与保存多个 Agent 应用。画布编排外层步骤，Agent 节点内部自主调用工具/委派专家。第一条验收样例为销售 CSV/Excel 分析报告。按需运行并绑定固定应用和脚本版本。
  - 后续：输入/输出、用户旅程、业务实体、成功与失败、工具与数据来源。
- R2：已确认单企业、多用户、可私有化部署的内测版本；具体容量和质量指标待确认。
  - 后续：组织/身份/权限、数据边界、集成、部署、运维、备份与恢复、容量与 SLO。
- R3：已确认每天约 8 小时，第一周为纵向切片，完整工程分阶段验收。
  - 后续：首版范围、优先级、开发切片、依赖与验收关卡。
- R1/R2 确认后：Agent/工作流拆分、意图与澄清、多 Agent 契约、状态、记忆和人工介入。
- 业务与执行契约确认后：数据模型、接口与事件、错误/恢复、缓存、预算、观测、评测与安全测试。
- 任务与数据基线确认后：是否微调、训练目标、数据划分、对照实验和模型部署。

## 第 2 轮：已回答

Q4 主创作者画像。用户选择：普通业务人员完全通过可视化操作创作。未接受技术人员优先的推荐；具体采用配置表单还是流程画布待确认。

Q5 Agent 的保存与执行语义。用户接受：保存可复用的 Agent 定义，执行时生成独立运行；保存数量不写死为少数预置角色，容量通过资源和配额定义。不默认每个保存的 Agent 都是常驻进程。

Q6 执行信任边界。用户选择允许上传脚本，未接受只接入可信开发者预置工具的推荐。语言、输入输出、脚本角色、发布权限、执行隔离、依赖和联网权限待设计；允许上传不表示允许直接在平台宿主执行。

## 第 3 轮：已回答

Q7 可视化创作交互。用户选择工作流画布，未采用表单配置为主的推荐。需明确画布编排哪些步骤，以及和自主 Agent 的关系。

Q8 脚本接入契约。用户接受首版支持 Python，将脚本封装为 Agent 可调用工具，具备声明的结构化输入输出与产物；由平台统一负责 Agent 调度和运行管理。

Q9 脚本访问权限。用户接受默认只访问本次授权输入和独立工作目录；联网目标、企业系统与凭据需显式授权；设置执行时间、内存与输出大小限制。隔离技术未选型，事实核查见 research/script-execution-options.md。

## 第 4 轮：已回答

Q10 画布与自主 Agent 的职责。用户接受画布定义外层步骤与分支，Agent 作为其中一种节点，自主完成节点内部的工具调用/专家委派。发布对象称 Agent 应用。

Q11 第一条验收业务。用户接受使用公开可复现的销售 CSV/Excel 分析模板：上传数据、脚本统计、Agent 分析、生成报告，另设计数据错误与执行失败案例。它是平台验收样例，不限制平台只能处理该业务。知识检索、多 Agent 与人工审批的后续样例尚需细化。

Q12 版本与运行关系。用户接受发布产生固定版本；运行绑定所选 Agent/脚本版本；作者后续改动形成草稿或新版本，运行中的任务不追随最新配置。权限和回滚细节待确认。

## 第 5 轮：已回答

Q13 使用入口与会话。用户接受首版以 Web 对话加附件上传为使用入口；一次提交产生一次应用运行，同一会话可包含多次运行。运行中的追加消息、审批恢复与 API 入口后续另定。

Q14 角色与发布。用户接受管理员/创作者/使用者的权限组合。创作者可以保存并在受限环境调试自己的草稿；组织内共享的应用和脚本工具经管理员审核发布。个人可兼任多个角色，具体矩阵待确认。

Q15 共享与数据边界。用户接受共享应用不自动共享用户的会话、上传文件与个人记忆；组织共享资料需单独授权。应用作者不因作者身份自动获得其他使用者的输入访问权。

Q16 画布拓扑。用户接受外层工作流为有向无环图，支持条件分支和并行汇合，禁止任意回边；Agent 节点内自主循环受轮数、时间和费用预算约束。具体节点清单与合并规则后续确定。

## 第 6 轮：已回答

Q17 意图识别位置。用户选择统一入口：直接向平台提需求，平台从已发布 Agent 应用中匹配。未接受先选择应用的推荐。匹配须遵守已确认的应用使用权限。原会话术语以单应用为上下文，跨应用切换语义需第 7 轮明确。

Q18 长期记忆策略。用户接受个人长期记忆默认按使用者与应用隔离，显式请求或确认后保存；模型自动提取的内容仅作为候选。用户可查看、修改和删除个人记忆。会话历史与长期记忆分别处理，组织资料单独授权。

Q19 同会话运行并发。用户接受一个会话同时最多一个活跃运行，后续普通任务消息排队；跨会话按配额并发。取消单独处理，不排在普通任务后；审批答复和排队细节后续定义。

Q20 部署目标。用户接受正式私有化交付面向 Linux，以 Docker Compose 提供初期可部署拓扑；脚本执行服务与应用服务分离。Windows 用于开发/客户端，可连接 Linux 执行服务；隔离运行时与具体资源待选定。

## 第 7 轮：已回答

Q21 会话跨应用语义。用户接受同一平台会话可跨运行切换应用，并显示本次处理者。切换时明确交接必要信息，不默认互通全部内部历史、文件和长期记忆。术语“会话”已细化为平台会话；交接内容和确认方式待细化。

Q22 匹配歧义。用户接受明确单一匹配时自动使用；多个适合应用时展示候选供用户选择；无匹配或缺少必要信息时澄清，不随意选择。只在用户有权使用的已发布集合内匹配；阈值须依验证数据设定。

Q23 单请求调用范围。用户接受一次需求路由到一个主应用；需要多 Agent 协作时由该主应用的流程和 Agent 节点委派。平台首版不隐式启动多个独立主应用并自行拼接输出。

Q24 发布用途说明。用户接受发布前必须提供用途、适用/不适用范围、必要输入、预期输出和示例需求等可供使用者理解及匹配的说明；可辅助生成，需创作者确认并审核。

## 第 8 轮：已回答

Q25 平台请求与应用运行。用户接受先形成平台请求，匹配并补齐必要信息后再创建绑定版本的应用运行；针对澄清的补充属于同一请求，不另行启动新任务。此项细化原 Q13 的一次提交与运行关系。

Q26 多 Agent 复用对象。用户接受主应用可显式选择其他已发布、具备调用权限的应用作为子任务能力，绑定版本，限制调用层数和次数并禁止循环依赖；子任务输入输出需有契约。被调用应用不得使发起者获得额外数据权限。具体画布节点和运行时适配待设计。

Q27 脚本依赖交付。用户接受脚本连同输入输出说明及依赖声明一起提交；调试/发布前准备固定依赖环境，正式运行不临时联网安装。第三方包的准入和构建失败反馈待细化。

Q28 组织知识库范围。用户接受完整首版包含基础的组织资料上传、授权检索及出处引用；与个人长期记忆分离。第一周仍以已确认的文件分析纵向切片为目标。

## 第 9 轮：已回答

Q29 完整首版节点范围。用户接受开始、结束、模型、Agent、脚本工具、调用应用、知识检索、条件分支、并行汇合、人工审批共十类；首周只实现验收流程所需子集，不将全部节点列为首周完成标准。

Q30 运行审批。用户接受涉及对外发送或修改企业系统等受控高影响操作时暂停，展示具体目标和参数，由有权限的发起者确认，批准绑定具体操作参数，之后继续原运行；拒绝或过期则终止本次运行。发布审核不代替运行审批；读资料和本地统计不默认逐次弹窗；批准不授予原本没有的权限。

Q31 失败与恢复。用户接受读取/纯计算有限重试，外部写入结果不明时暂停核对而非盲目重发；恢复复用已确认完成的步骤结果，保留错误与部分产物，不默认从头重跑。具体并行失败、重试次数、降级模型和状态机随后定义。

Q32 身份接入。用户接受首版使用管理员创建/邀请的本地账号与已确认角色权限，不开放公有自助注册；企业 OIDC/SSO 作为后续接入能力。

## 第 10 轮：已回答

Q33 容量验收基线。用户接受完整首版的验收画像为 100 个用户、1000 个已发布应用、20 个同时执行的顶层运行；子任务和脚本另有资源配额。仅为计划目标，尚非能力实测或产品硬上限。平台替身压测与真实模型小规模实验分别记录。

Q34 模型降级。用户接受管理员预先授权主/备用模型；有限重试后仍遇到可用性故障才切换，先检查工具和输出契约，记录原因及费用；不直接拼接两个模型的半段输出，不因内容质量不确定而无限换模型；预算耗尽停止。

Q35 缓存边界。用户接受首版缓存有清晰身份/权限/来源版本的检索与确定性只读工具结果；个性化最终答案不跨用户共享，外部写操作不做结果缓存替代执行核对。近似语义答案缓存后续经评测再考虑。

Q36 主开发栈。用户选择 Go 后端，画布使用 bcakmakoglu/vue-flow，未采用 Python 主后端与 React 的推荐。Vue Flow 使用 Vue 3；TypeScript 建议待架构复核。是否保留 Python 作为 LangGraph/DeepAgents 执行层，必须单独确认；不能将“Go 后端”自动解释为放弃这些 Python 框架。

## 第 11 轮：已回答

Q37 Go 与 Python 边界。用户接受 Go 负责用户/API/应用版本/发布审核/权限/路由协调/任务管理，Python worker 负责 LangGraph 整个工作流执行及 DeepAgents 节点。Vue 3 + Vue Flow 负责画布，前端图数据转换为平台自己的执行定义。未选择 Go 自行执行整个画布 DAG 的方案。

Q38 微调交付范围。用户在开源参考说明后明确回复“确认”。采用 LlamaFactory 离线 LoRA 实验、独立评测、管理员模型登记，优先验证动态候选应用路由；第一轮使用自建或公开数据，真实用户数据需另行授权。业务人员在线训练工作台、DPO 和强化学习后续按数据与需求展开。TRL 和 MLflow 作为参考或可选工具，不同时强制部署。未执行训练。

Q39 运维诊断内容可见性。用户接受后台默认展示脱敏运行元数据与操作审计；提示词、文件正文、结果正文仍按用户数据权限控制。运维排障读取正文需用户显式授权并留痕；后续观测接入必须遵守此边界。

Q40 删除与保留。用户接受可删除自己的会话/任务文件/个人记忆，相关检索和缓存停止可用；组织审计保留必要元数据、不因此保留完整正文；备份按保留周期淘汰，明确逻辑删除和物理清理差异。默认期限与清理参数由详细方案提出供复核。

## 第 12 轮：已回答

Q41 模型数据去向。用户确认支持管理员批准的外部 API 和内网模型端点，应用显示模型数据去向；私有化平台不代表所有模型必然本地运行。完全离线交付需另行调整模型与镜像范围。
