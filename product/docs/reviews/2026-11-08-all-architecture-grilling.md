### Q7：共享页面状态模块加载失败

**问题：** 是否明确显示“运行状态暂不可用”，暂停受影响的实时状态展示和相关操作，保留导航与重新加载入口？

**建议：是。** 当前真实页面正常加载共享脚本，但资源 404 或语法错误后浏览器仍可能运行页面脚本。旧 fallback 会以另一套规则解释状态。另一选择是仅展示明确标注“未解释”的原始快照。

**用户答复：已确认。** 2026-11-08，用户回答“两个都按推荐”，接受本题推荐方案：明确显示“运行状态暂不可用”，暂停受影响的实时状态展示和相关操作，保留导航与重新加载入口。受影响操作的具体范围需要在设计中列明并验收，不把导航等无关功能一并锁死；不采用“展示未解释原始快照”的替代方案。

### Q8：三条知识读取路径的完整性标准

**问题：** 是否让普通检索、打开引用、缓存命中都校验封存正文与记录的 SHA-256、字节数一致，拒绝返回损坏内容？

**建议：是。** 增加普通读取的校验成本，以免缓存失效后未校验的 miss 路径又返回损坏内容。保留各入口既有错误表达：检索跳过不可读片段且不缓存部分结果；引用不返回不可读正文；瞬态故障不永久删除有效缓存。

**用户答复：已确认。** 2026-11-08，用户回答“两个都按推荐”，接受本题推荐方案：三条路径都校验正文 SHA-256 和字节数，拒绝返回损坏内容，同时保留上述入口错误策略。不采用“只统一结构、保持不同校验强度”的替代方案。本次增强必须在规格中明确，不倒写成原始实现已满足的事实。

## C2：模型尝试生命周期

### 已核对的事实与保持的语义

- [service.go](../../internal/capabilities/service.go) 的 `beginModelAttempt`、`finishModelSuccess` 已共享部分预留和结算；目标是收拢剩余编排，不能只抽取候选对象就宣称完成。
- [stream.go](../../internal/capabilities/stream.go) 有每次尝试独立 generation、失败草稿丢弃、完整工具调用缓冲、最终封存与消费断开处理；这些流式职责仍有独立存在的理由。
- [ADR 0035](../adr/0035-t122-openai-compatible-adapter.md) 固定 adapter 单次物理请求、service 最多三次主尝试和一次兼容 fallback。权限、Schema、工具参数拒绝不重试；取消不重试、不 fallback。调用前未通过部署门禁不伪造 attempt。
- 成功响应后平台校验或封存失败，不能抹掉已发生的消费；按实际候选费率结算。缺失 usage 的预留语义保持。
- 普通业务取消的现有记账策略与兼容验证取消探针不同：后者 usage 未知时保留预留、费用与 tokens 为 NULL。此次结构重构不把探针政策扩展到普通业务。job 账本与 run 账本也不合并。

### 必须完成的设计与验证

共享职责覆盖：候选选择、调用前门禁、预留、attempt 开闭、物理调用次数、失败分类、受控重试/fallback、取消清理、成功结算。沿用现有 Provider / StreamProvider seam，内容收集分别处理。

静态核对发现以下差异，均先做定向复现，不能直接写成已确认线上缺陷：

1. 同步路径对已派发的 adapter 类错误与流式路径的重试/fallback 路由不同；区分派发失败和调用前未配置。
2. 流式 retry/fallback 通知忽略 emitter 错误，可能在消费者停止后继续发起下一请求。
3. 部分流式失败清理忽略数据库错误，可能使账本仍为 dispatching。
4. 同步、流式、fallback 的尝试前取消检查及退避处理不完全一致。

验收必须观察实际请求数、attempt/operation 和预算记录、封存结果、generation，而非仅检查 helper 调用。覆盖调用前/中/退避取消、终态拒绝、三主一备上限、失败释放、响应后失败计费、缺 usage、半条流与工具参数、消费者断开、清理失败。

已有回归入口：`tests/f06/test_t044_streaming.py`、`test_t045_fallback.py`、`test_t046_budget.py`、`test_t122_real_provider.py`，以及 capabilities/modelproxy Go 测试。真实 PG 与本地 fake HTTP provider 的证据和真实供应商验收分栏记录。

## C3：组织知识库可读片段

### 已核对的事实与保持的语义

- [readable_chunk.go](../../internal/knowledge/readable_chunk.go) 已唯一维护 owner、tombstone、活动 ready 索引、片段 revision、正文 artifact 就绪及归属 SQL；无需再建第二份权限谓词。
- [service.go](../../internal/knowledge/service.go) 的普通检索和 `GetChunk` 经有上限的对象读取，但没有完整执行与缓存命中相同的正文校验。缓存复检见 [cache_store.go](../../internal/knowledge/cache_store.go)。Q8 已确认三条路径统一校验正文 SHA-256 和字节数，属于待实施增强。
- [ADR 0018](../adr/0018-f10-index-revisions.md) 允许重建期间或失败后继续读旧活动索引。因此不能简单要求“活动 revision 必须等于最新源 revision”或“文档当前状态必须 ready”。新检索要求与当前 embedding 模型兼容，打开既有引用不应额外要求当前 embedder 相同。
- [ADR 0015](../adr/0015-f10-retrieval-cache.md) 允许普通检索跳过不可读正文、返回部分或空结果，但不缓存部分/空结果。缓存遇瞬态读取错误按 miss 处理并保留条目；确定性不可读可丢弃条目。引用打开不可读返回 404；回答返回前复检引用失败不能输出带失效引用的最终答案。
- 缓存不能掩盖 embedding 不可用；正文不跨用户复用；最终答案不缓存。删除与撤权后的不可读性不能依赖 TTL 或异步驱逐。

### 必须完成的设计与验证

共用读取结果应表达经验证正文及内部可区分的故障，让各入口保留上述公开错误策略。按已确认的 Q8 纳入记录的摘要和字节数校验；不把所有 I/O 错误统一改成永久损坏或整个请求 503。

两项组合风险要定向验证：

1. 活动索引来自源 A，替换为 B 正在重建或重建失败，再删除 A；确认旧活动索引不会绕过来源删除规则。当前普通删除已有事务级派生资源 tombstone，不能仅因 SQL 未连接源表就认定全部删除可绕过。
2. 数据库 artifact 摘要不变而宿主对象字节被替换；对比缓存命中、miss、引用和回答。现阶段仅确认校验强度有差异，尚未证明完整攻击链。

验收覆盖缓存开关对照、正文篡改/截断/大小不符、对象缺失、瞬态占用恢复、撤权/删除、旧活动索引重建失败、新索引激活后旧引用失效、引用返回前再次失效。不得扩大 ACL 或借错误暴露对象路径/正文。

已有回归入口：`tests/f10/test_t061_index_versions.py`、`test_t064_answer.py`、`test_t067_cache.py`、`tests/f11/test_t069_resource_deletes.py`、`tests/f13b/test_t113_cache_comparison.py`，以及 knowledge Go 测试。
