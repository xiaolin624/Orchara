04 · 服务账号与 API Key

服务账号与 API Key

服务账号是独立 principal：没有登录密码、没有角色，只能用带 scope 的 API key 访问；每个动作仍要满足资源 ACL。

创建服务账号（具名负责人）

负责人必须是已启用的人类用户；负责人被禁用后，该账号的 key 立即失效（无需逐把撤销）。 负责人只是治理归属，不会把 TA 的个人应用或记忆借给服务账号。

服务账号已创建，主体 ID：—

它不能登录，也没有角色；请把该 id 填进下面的 API key 表单。平台只保存负责人归属，不会把负责人的个人数据授权给它。

签发 API key（scope + 资源 ACL）

F01 只开放 application:read。scope 表示“这类动作被允许”， 具体应用仍需在资源授权里显式授予 read，两者同时满足才可读； 个人/记忆 scope 对服务账号一律拒绝。key 明文只返回一次，平台只保存 SHA-256。

05 · 审计

审计

管理台写出的管理操作会在同一事务里追加到 platform.audit_events（actor、action、resource、metadata、时间）。当前版本没有提供审计记录的读取接口，因此管理台不展示审计记录，也不伪造列表；下面列出真实写入的动作。

管理台操作审计 action记录内容

审计事件只由服务端写入；本版本没有修改或删除审计记录的接口。禁用/启用的原因会原样写入 metadata，因此该字段必填。

使用说明与技术详情

本页先向 /api/v1/auth/me 读取当前身份，刷新后仍然记得你是谁； 未登录会跳转到登录页。邀请返回的一次性激活令牌与创建 API key 返回的一次性明文都 只显示一次，平台只保存它们的哈希，请人工转交/立即保存。 资源授权、角色修改、服务账号与 API key 也在这里，写入都会带本会话的 CSRF 令牌。
