使用说明与技术详情

提交 POST /api/v1/applications/{id}/debug-runs 会把指定的草稿 revision 冻结成仅自己可见的执行快照，并创建一个 kind=debug 的 queued Run。调试不创建公共版本、 发布审核、平台 Request 或 Conversation；草稿随后如何修改都不会改变已经创建的 Run、快照和输入字节。 提交必须带 Idempotency-Key：同一 key 与同一请求会重放原来的 Run，不会创建第二个。 调试需要 creator 角色（管理员也需兼任），否则服务器返回 403 creator_role_required。 提交成功后本页用 GET /api/v1/runs/{id} 显示 Run 的 state / phase / kind / revision / execution_snapshot_id，以及服务器返回的真实租约事实 （X-Run-Attempt-Started-At / X-Run-Lease-Deadline，仅在尝试存活时出现）。 领取、心跳与退出证据由 F03 内部 supervisor 协议完成；页面不伪造进度。

执行阶段：executing → finalizing → 终态。finalizing 表示结果提议已保存、 仍在等待 supervisor 的退出证据（进程/沙箱/数据库排空），本页不会在终态前显示成功；页面会持续轮询 GET /api/v1/runs/{id} 直到服务端提交终态。持久时间线来自 GET /api/v1/runs/{id}/events（SSE，按 Last-Event-ID 重连、按 seq 去重）， 关闭/断线不会中断服务端业务；窗口过期时服务端回 410，页面改用 Run 快照。

手机支持对话、审批和查看结果；完整画布编辑不承诺在手机上可用，请使用桌面浏览器。
