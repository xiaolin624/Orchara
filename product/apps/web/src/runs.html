使用说明与技术详情

列表来自 GET /api/v1/runs：只显示你拥有的 Run（管理员没有超级用户读权限， 同样只看到自己的）。详情来自 GET /api/v1/runs/{id}。运行中的 Run 显示服务器返回的 真实租约事实（X-Run-Attempt-Started-At、 X-Run-Lease-Deadline，来自数据库时钟）；没有租约事实时本页不伪造进度。 领取、心跳与退出证据属于 F03 内部 supervisor 协议，普通页面只读它们的结果。

执行阶段：executing → finalizing → 终态。finalizing 表示 worker 的结果提议已保存， 但仍在等待 supervisor 的退出证据（进程/沙箱/数据库排空）；在终态提交前本页不会显示成功。 详情页会在 Run 未进入终态时轮询 GET /api/v1/runs/{id}，进入终态后停止。 累计活跃时间来自同一响应的非契约响应头 X-Run-Active-Elapsed-Ms / X-Run-Max-Active-Ms / X-Run-Deadline-Exceeded（契约 Run 没有这些字段）： 跨尝试累计为一个时钟，新 attempt 不重置；上限为 NULL 表示未知/无截止，不是 0。 持久时间线来自 GET /api/v1/runs/{id}/events（SSE，id: seq、 event: type、data: event.schema 封套）。断线后客户端按 Last-Event-ID 重连并按 seq 去重；服务端若返回 410 事件保留窗口过期，页面改为显示 details.snapshot_url 指向的 Run 快照，而不是伪装完整历史。

等待审批/子任务（F03/T035）：worker 在固定 checkpoint 停止后，Run 进入 waiting_approval / waiting_children（phase=waiting），等待事实保存在 platform.run_waitings。等待期间释放 worker 执行槽，但 逻辑会话槽与 Run 一直占用到终态：等待与恢复排队都不是终态。 只有“解决结果 + supervisor 退出确认 + checkpoint”齐全后才创建唯一恢复任务 （jobs.kind=resume，携带封存的 canonical 恢复输入）。等待/决定/退出/恢复事实由非契约 响应头 X-Run-Waiting-Kind / X-Run-Waiting-Outcome / X-Run-Waiting-Decided-At / X-Run-Waiting-Exit-Confirmed-At / X-Run-Resume-Job-ID / X-Run-Resume-Job-State 提供；本页不伪造批准、 不显示恢复输入内容，也不把 202/200 解释为已恢复。

取消（F03/T036）：owner 可在详情中调用 POST /api/v1/runs/{id}/cancel （幂等；会话带 CSRF，API key 需 application:write）。取消只表示接受停止意图： 有活动执行单元时 Run 进入 cancelling（正在停止），结果/登记/新上传/审批调用被拒绝， supervisor 退出证据齐全后才提交 cancelled（已停止）；存在未知外部写时转 needs_reconciliation，不假装取消已撤销远端效果。迟到结果/事件不会把终态翻回。

保守恢复（F03/T038）：租约超期的 Run 只会被挂起在 recovery_pending（recovery_reason=lease_expired），supervisor 已确认退出但没有结果的 Run 挂起为 exit_without_result。挂起期间 job 保持 held、执行槽仍占用、旧 attempt token 不被替换；不会自动接管，也不会创建第二个 执行者（claim 只选 queued Run）。只有运维在证明旧执行单元/沙箱已销毁、checkpoint 数据库连接 已排空、冻结 manifest 与输入仍可用之后，用 orchara-admin runs sweep-leases --grace 60s [--dry-run]（只挂起）与 orchara-admin runs recover --run --evidence [--check-only] 重新排队；本页只显示原因、挂起时间与是否已有受审计证据，不提供伪造的“恢复”按钮。 恢复事实由非契约响应头 X-Run-Recovery-Reason / X-Run-Recovery-Since / X-Run-Recovery-Evidence-At / X-Run-Recovery-Evidence-SHA256 提供；终态不会因恢复证据而改变。

手机支持对话、审批和查看结果；完整画布编辑不承诺在手机上可用，请使用桌面浏览器。

        正在加载子运行…

          子运行是独立 Run：有自己的 id、attempt、checkpoint thread 和结构化结果；点击“查看”打开它的详情。 本页只显示服务端返回的 Run/结果，未进入终态的子运行不会显示为成功。 同一父调用键重放会复用原 child；不同 invocation key 的并发调用是两个独立 Run， 不会按应用 ID 合并。子运行使用父 Run 的 owner 执行；父版本未固定的子版本不可调用。

          临时模型流式预览（F06/T044）：等待当前 generation 的临时 delta。每帧带 operation/generation；半流失败后旧草稿整体丢弃并由新代次替换；工具片段只显示“待定”， 不执行。预览不持久，最终以持久 Run 快照/事件为准。
