本页是非契约的评测进展视图（ADR 0018）：轮询 GET /api/v1/evaluations/{id}/progress 显示已持久化的逐例计数， 再从契约读 GET /api/v1/evaluation-reports/{id} 显示不可变报告。 刷新不会丢状态：评测 id 在 URL 路径里，页面重新读取同一份服务端事实。 页面不把 state 换算成百分比，也不伪造进度条：数字只来自 runner 在每例结束时写入的判定。

“报告失败”与“任务失败”是两件事

业务失败（报告 failed，任务 succeeded）： 平台完成了评测，密封报告给出的是对被评测应用的判定。 这表示应用的某些案例没有通过，或者案例没有被判为通过；它不是平台故障， 报告仍然可读、不可变。

设施失败（任务 failed，没有报告）： 评测任务没有执行完，平台没有产出任何报告，所以 report_id 为空。 这属于任务/平台侧失败，不能当成应用判定；原因码来自任务的 error_code。

not_run 是报告状态，不是任务状态： 一份 not_run 报告表示没有任何一例产出可判定结论（例如目标类型在本构建不可执行）。 对应的评测任务仍然是 succeeded，任务失败只会表现为 failed 且没有报告。

页面只展示服务端事实：failure_class=business 当且仅当存在报告且报告不是 passed； failure_class=infrastructure 当且仅当任务失败且没有报告。
