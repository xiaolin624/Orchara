## 1. 变更范围

本票只改 Go 执行运行时 `internal/presetexec`，不新增公开端点、迁移、契约或规格文本。

| 文件 | 变更 |
|---|---|
| `internal/presetexec/nodeexec.go`（新增） | `nodeExecution` 受约束的节点执行输入；`nodeOutcome` typed 局部决定（succeeded/failed/cancelled/waiting，携带输出、checkpoint proposal、sandbox 事实与退出证据）；`applyGraphNodeOutcome` 图调度器映射。
| `internal/presetexec/agent.go` | Agent 循环改为接收 `*nodeExecution` 并返回 `nodeOutcome`；删除对 `linearRun`/`linearPlan` 的依赖；`agentFailed`/`agentCancelled`/`agentWaiting` 只发布节点自身事实并返回决定，不提交 Run、不跳过、不排空；工具/子应用失败同样返回局部决定。
| `internal/presetexec/agentcontext.go` | `agentContextScope`/`resolvedAgentInputs` 只读 `nodeExecution` 的 namespace 快照与 sealed node-id 快照；绑定来源 kind 由 sealed definition 的节点类型判定，不再引用 `linearPlan`。
| `internal/presetexec/linear.go` | 线性调度器构造 `nodeExecution`（namespace/scope/sandbox 快照），新增 `runLinearAgentNode` + `commitLinearNodeOutcome`：由调度器统一执行 skip、failed proposal、exit 证书、waiting 提交；删除 `linearRun.scopeIDs`。
| `internal/presetexec/graphrun.go` | `executeGraphAgent` 用 `newGraphNodeExecution` 构造显式输入，经 `applyGraphNodeOutcome` 写入 `graphNodeAttempt` 并交给既有 `commitFailure/commitCancelled/commitWaiting`；`graphLinearView` 仅剩 `executeGraphCallApp` 使用。
| `internal/presetexec/callapp.go` | 抽出 `classifyChildResult`（scheduler-neutral child 决定）；Agent 子应用路径改为返回 `nodeOutcome`（success/failure/waiting），call_app 仍走原 `failDelegation`/`waitForChild` 行为（#153 迁移）。
| `internal/presetexec/presetexec.go` | `failAfterStart` 拆为 capture-aware wrapper 与调度器可用的 `commitFailedAfterStart`；线性调度器不再经过隐藏 context 捕获。
| `internal/presetexec/nodeexec_test.go`（新增） | 6 个 seam 测试（见 §4）。 |

`plan.go` 未改：`linearPlan` 仍是线性调度器自己的计划事实；本票让 Agent 不再消费它。
`graphLinearView` 按票面要求保留，等 #153（call_app）迁移后由 #154 删除。

## 2. 新 interface 形状

```go
// 受约束的节点执行输入：由 owning scheduler 从权威调度事实构造，启动时快照。
type nodeExecution struct {
    node          *manifestNode
    definition    *manifestDefinition // 只用于按 sealed 节点类型归类绑定来源
    inputs        []InputArtifact
    namespace     map[string]any      // 上游输出命名空间，启动时复制
    startNodeID   string
    scopeNodeIDs  []string            // sealed node-id 授权范围，启动时复制
    agentConfig   *agentConfig        // 调度器已证明的节点配置
    sandbox       sandbox.Outcome     // 节点启动前已有的 sandbox 事实
    report        *SandboxReport
}

type nodeOutcome struct {
    kind    nodeOutcomeKind // succeeded | failed | cancelled | waiting
    output  map[string]any  // succeeded：已校验且已注册的输出
    code    string
    message string
    sandbox sandbox.Outcome // 节点自己最新 sandbox 事实（含 SandboxStarted）
    report  *SandboxReport
    evidence        map[string]any // 调度器排空后提交的 exit 证据
    failureEvidence bool
    startedForExit  bool
    proposal        *Proposal      // waiting：checkpoint（capability:<op> / child:<id>）
    outcomeName     string         // waiting：waiting_approval / waiting_children
    fallbackCode    string
    proposalRefusal string
    exitRefusal     string
}
```

调度权威分工：

- **图**：`executeGraphAgent` → `applyGraphNodeOutcome(attempt, outcome)`，只写
  `graphNodeAttempt`；随后既有 `stopAndCommit` 执行 `cancel`、`drain`、`skipUnsettled`、
  `emitPendingSkips`，并由 `commitFailure/commitCancelled/commitWaiting` 唯一提交。
- **线性**：`runLinearAgentNode` → `commitLinearNodeOutcome`，由线性调度器执行
  `skipRemaining`、failed proposal、cancel exit 或 waiting 提交；节点代码不再接触这些。
- 节点自身只发布自己的 `pending/running/failed/succeeded` 观测事实（成功事实仍然是
  “已注册输出”之后的最后一步）。
