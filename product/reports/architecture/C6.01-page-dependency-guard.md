## 2. 显式共享状态 interface（guard 要求的完整表面）

`runstream.js` 新增 `globalThis.OrcharaRunState`（冻结对象，`interfaceVersion: 1`）。guard 逐项检查
并区分 `missing`（404/解析失败，无命名空间）与 `incomplete`（可解析但缺项）：

| 导出 | 类型 | 用途 |
|---|---|---|
| `interfaceVersion` | number，必须 `=== 1` | 页面与 guard 同批发布；版本不符即依赖失败 |
| `view` | function | 状态/动作/文案投影（设计中的 `view(facts)`；当前签名为 `(run, facts)`） |
| `failure` | function | 流失败分类（410/401/404/transient） |
| `correct` | function | 410 安全快照重建（`await correct(failure, options)`） |
| `snapshotCorrection` | function | 同步快照修正（页面现有 410 路径使用） |
| `snapshotPath` | function | 同源快照路径选择 |
| `safeSnapshotPath` | function | 同源 `/api/v1/runs/...` 安全校验 |
| `isTerminal` | function | 终态判定 |
| `stateLabel` / `phaseLabel` | function | 契约枚举逐值文案 |
| `cancelAcceptedText` | function | 取消回执（不声称已撤销外部写） |
| `handlingText` | function | `/chat` handling 文案 |
| `shouldPoll` | function | `dispatched` 后继续观察 Run 的轮询规则 |
| `childSummary` | function | 父子 N/M 等待投影 |
| `artifactReadout` | function | 产物 readiness（最终/未完成/中间/未就绪） |
| `states` / `phases` | object | 冻结字典 |

**暂留旧出口（#156/#157 迁移，#158 删除）**：`runStreamTruth`、`runStreamFailure`、
`runStreamCorrectFromSnapshot`、`runStreamSnapshotCorrection`、`runStreamSnapshotPath`、
`runStreamSafeSnapshotPath`、`runStreamIsTerminal`、`runStreamStateLabel`、
`runStreamPhaseLabel`、`runStreamCancelAcceptedText`、`runStreamHandlingText`、
`runStreamShouldPoll`、`runStreamChildSummary`、`runStreamArtifactReadout`。
Node 用例逐项断言仍存在，且 10 个核心导出与 namespace 条目是**同一函数引用**，不是第二套实现。

guard 资产：`apps/web/src/assets/runstate-guard.js`，由 `GET /assets/runstate-guard.js` 静态服务；
`OrcharaRunStateGuard = { MESSAGE:'运行状态暂不可用', REQUIRED, status, ready, check, apply }`。
`check(scope)` 只读命名空间、不碰 DOM；`apply(document)` 才写 banner/禁用控件，且 **ready 时立即
返回、完全不改页面**（正常路径零行为变化）。真实页面在 guard 之后才加载页面脚本，因此控件已存在。

`disabled`（运行视图开始后才启用），所以故障验收用 `data-runstate-paused-applied="true"` + `disabled`
