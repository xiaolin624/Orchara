## 4. 关键行为证据（Node，真实字节）

- **正常状态**：chat `describeHandling` 覆盖 queued/running/finalizing/succeeded/failed/cancelled/
  cancelling/waiting_children/waiting_approval/recovery_pending/needs_reconciliation；runview
  `formatRunError` 覆盖同一组并保留节点错误码 hint。
- **dispatched 后继续观察**：DOM harness 中请求保持 `dispatched`，Run 序列
  `queued → running → running(finalizing) → succeeded`，页面真实发起 4 次 Request 读 + 4 次 Run 读，
  在第 3 个 timer turn（succeeded）停止并显示“Run 已进入终态 succeeded。”。
- **轮询上限**：Run 永不终态时，`poll(0)` + 100 个 timer turn（attempts 1..100），attempts==100
  停止，共 102 次 Run 读，未扩大上限。
- **选择切换 + 迟到响应**：两种路径都以 generation 丢弃旧响应，面板保持 B。
- **取消意图 vs stopped**：runview cancel 收到 `cancelling` → “已接受取消意图…不会撤回”，按钮变
  “再次请求取消（幂等）”且可再次点击；收到 `cancelled` → “已停止（cancelled）…不表示撤回”，
  按钮禁用。
- **依赖失败**：命名空间缺失时 chat/runview 都显示“运行状态暂不可用”，且不发起 Run/取消请求。
