## 实现：按能力命名的观察 module

新增 `product/tests/support/run_observations.py`，只读取产品已经提交或已经暴露的事实，不准备数据、不启动执行、不生成期望值：

| 能力 | 入口 | 读取的真实事实 |
| --- | --- | --- |
| 节点结果 | `node_results_response` / `wait_node_results` / `node_result_items` / `node_data_rows` / `node_result_rows` | owner-only `/runs/{id}/node-results`（含 404 语义）与 `platform.run_node_outputs`  provenance 行 |
| 封存正文 | `artifact_content` / `artifact_document` / `node_data_document` / `sealed_object_bytes` / `sealed_object_text` / `sealed_object_document` | owner-only artifact content 路由；真实对象目录中的封存字节 |
| 状态 / SSE / 事件 | `node_events` / `node_states` / `sse_node_states` / `wait_run_state` / `output_artifact_id` | 持久化 `platform.run_events`（node.status 投影）、owner-only SSE 回放、`platform.runs` 已提交终态与 output 指针 |
| 最终输出 | `final_output_document` | 已提交 Run 的 `output_artifact_id` + 该产物的封存字节 |

与执行能力的分界保持不变：proposed result 仍由 worker 协议提交，supervisor 进程报告仍只由 `execution_support.execute_once` 解析；本 module 的 Run 状态读取只认 `platform.runs` 的 committed 行（`wait_run_state` 基于 `t031.run_state_row`）。因此“worker 提议 / supervisor 退出报告 / DB 已提交终态”三者没有被合成一个成功生成器。
