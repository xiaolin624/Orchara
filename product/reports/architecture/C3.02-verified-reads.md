## 1. 交付内容

### 1.1 `Service.GetChunk`（`service.go`）→ `reader.Open`

迁移前：自拼 `readableChunkColumns` 的旧投影（无 `size_bytes`/摘要校验）+ `readChunkText`。
迁移后：

```go
chunk, err := s.reader(ownerID).Open(ctx, chunkID)
if err != nil {
    if errors.Is(err, ErrNotFound) { return ChunkView{}, ErrNotFound }
    return ChunkView{}, err
}
return ChunkView{ ... chunk 的身份/citation/span, DocumentState: StateReady }, nil
```

- 不可读（不存在的/他人的/已 tombstone/被取代 revision/正文 artifact 非 ready）仍是既有
  `ErrNotFound` → 公开 404 `resource_not_found`，且不返回正文/对象键/路径。
- metadata 缺失/非法、对象缺失、摘要/大小不符同样是 `ErrNotFound`：公开面仍是同一个 404。
- metadata **整体 SQL 失败**仍返回 error（→ 500），不会被伪装成"不可读"。
- `Open` 不含 embedding model 条件：已有引用不要求当前 embedder 相同（§2 AC4）。
- `Answer` 不需要单独实现：它逐引用调用 `GetChunk`，迁移后自动走同一已验证读取；回答前复检
  失败（含字节被换/长度不符/大小 metadata 不符）返回既有 `citation_unreadable` 409，不返回
  任何 answer/citations 字段。

### 1.2 缓存命中（`cache_store.go`）→ `reader.CheckCached`

`cachedRetrieval` 的逐项复检从 `validateCachedItems` 改为：

```go
ok, reason := s.reader(key.PrincipalID).CheckCached(ctx, key.KnowledgeBaseID, items)
if !ok {
    if reason == CacheDiscardUnavailable { ...保留行，本次 miss... }
    s.discardCacheEntry(ctx, key); ...删行，本次 miss...
}
```

- 与检索/引用打开共用 `currentReadableChunkSQL`、`readableChunkColumns`、`readVerifiedBody`
  和 ADR 0015 D6 的五词 reason 表；不再有第二份 SQL / 第二套 provenance 比较 / 第二套字节读。
- 当前 provenance（document/revision/chunk/artifact id/hash）先比；随后同一有界读取校验
  `size_bytes` 与 `sha256`；再比 stored text 与验证后正文。
- 保留已接受故障策略：确定性（对象缺失/非法 key/超限、metadata 缺失/非法、长度/摘要不符、行
  不可读）→ 整条 discard；瞬态（I/O、文件被独占、校验 SQL 失败、cache 表暂不可用）→ 本次 miss
  且保留行（`cache_unavailable`），恢复后可再命中。
- 缓存键/TTL/source digest/owner/版本规则未改；embedding 检查仍在 cache lookup 之前（§2 AC4）。

## 5. 需要记录的解释（行为取舍）

1. **cache reason 的精确映射**：live entry 上 `sha256` 变成 NULL/非法时，`CheckCached` 先在
   provenance 比较处发现它与 stored hash 不等，返回 `item_mismatch`；`size_bytes` 缺失/0/超限
   则到达 verifier 后返回 `item_unreadable`。两者都是确定性丢弃，词表仍是 ADR 0015 D6 的五个词，
   没有新增 reason。本票按此断言。
2. **被权限谓词过滤的 chunk 不算 partial**：把正文 artifact owner 改成他人后，该 chunk 不再进入
   候选 SQL，因此 `skipped=0`，剩余完整结果可以按同一 cache key 重新存储（`stored=true`）。这是
   既有 `skipped` 语义（只统计 SQL 可见但字节不可验证的候选），不是本票新行为；真实用例显式断言
   新行不含该 chunk，恢复后清缓存再证明三路可读。
3. **citation 打开的瞬态读失败仍映射 404**：`reader.Open` 把所有正文拒绝（含瞬态）映射为
   `ErrNotFound`，与迁移前 `readChunkText` 失败 → 404 完全一致；回答复检得到
   `citation_unreadable` 409（fail closed，不返回可能失效的答案）。
4. **回答路径没有独立的生产代码改动**：`Answer` 已经逐引用调用 `GetChunk`；本票迁移
   `GetChunk` 即把回答复检接入同一已验证读取。新增真实栈用例证明这一点（生成窗口内改
   `size_bytes` → 409）。
5. **`cacheDiscardDecision` 内联后删除**：keep-vs-delete 决定仍只在 `cachedRetrieval` 一处，
   判定词仍是 `CacheDiscardUnavailable`；不在 reader 里做删行（reader 只回答"能否继续提供"）。
