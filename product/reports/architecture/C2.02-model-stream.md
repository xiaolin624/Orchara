## 1. 交付内容

### 1.1 流式内容半边接入同一 `modelAttemptSession`（`internal/capabilities/stream.go`）

设计 C 的 operation session 从 C2.01 起是私有实现；本票让 `Stream` 也使用它，而不是自己再写一套
候选/预留/重试/fallback/关闭循环。

- `Stream` 照旧完成 role/authorization/manifest/params/operation 准备与 replay 分支；非 replay
  路径装配 `newModelAttemptSession(..., streaming=true)` + `streamModelContent`，然后只调用
  `session.dispatch(ctx, modelContentHandler{...})`。
- `modelAttemptSession` 新增 `streaming` 选择：`candidate()` 通过
  `Providers.StreamingFor` 取真实 `StreamProvider` 并在任何预留/attempt 行之前执行
  `Available`（不能流式的候选现在在派发前诚实拒绝，不再先写 attempt 再失败）；同步路径仍用
  `Providers.For`。两者共用同一候选、授权、预算与账本门禁，没有把同步调用伪装成 SSE。
- `streamModelContent` 是内容半边，拥有本票保留的“流式实际内容差异”：
  - `call`：恰好一次 `StreamProvider.Stream`；每个 chunk 进入本次 attempt 独立
    `streamGeneration` 并投影为带 `generation_id = operation_attempts.id` 的帧；emit 失败会
    停止 provider 并以 `errStreamConsumerStopped` 包装（分类为取消，绝不重试/fallback）。
  - `complete`：本代文本必须与 provider 的完整文本一致；`tool_calls` 只取本代
    `completeToolCalls()`（不完整/畸形调用已在缓冲区丢弃），再走与同步完全相同的
    `finishModelSuccess`（校验/封存/结算）。文本不一致仍按真实 usage 结算；封存失败仍按既有
    `failModelAttemptAfterSuccess` 规则消费；`final` 帧投递失败时已封存的成功保持。
  - `notice`：retry/fallback 的临时可重试错误帧（带失败 attempt 的 generation id）。
  - `failed`：已写入账本的终态 provider 失败帧（primary/fallback 各自文案）。
- 删除 `dispatchStream` 与 `dispatchStreamFallback`（含重复的候选解析、预留、费率、关闭、结算
  编排，约 280 行）。没有留下兼容别名或待删 wrapper。

### 1.2 统一驱动补上流式投递语义（`internal/capabilities/attempt.go`）

- `modelContentHandler` 新增 `Notice`（重试/fallback 通知，返回错误即消费者已停止）、
  `Failed`（终态失败帧，不得改变结果）、`CancelCode`（`caller_cancelled` /
  `stream_cancelled`）。
- driver 在每次重试与 fallback 之前投递通知；通知返回错误时 `stopOperation`：已按 provider
  失败码关闭的 attempt 保持原样（provider 确实失败了），operation 以本次入口的取消码终结，
  不再派发任何 attempt/fallback。
- `sleepBackoff` 取消同样走 `stopOperation`（通知已投递后消费者在退避期消失，不创建下一次
  attempt）。
- `finishCallerCancelled` 泛化为 `finishCancelled(ctx, operationID, attempt, code)`，流式入口用
  `stream_cancelled`、同步入口用 `caller_cancelled`；清理仍使用脱离已取消请求的 5s 有界
  context。`modelCallFailureCode` 把流式消费者停止识别为取消（`stream_cancelled`）。
- fallback 的 attempt_no 继续使用 C2.01 §5 的稠密规则：`fallback = 最后一个主 attempt + 1`，
  adapter 类早退是 `[1,2]`，三次 transient 后是 `[1,2,3,4]`，不再有 `[1,4]` 空洞。

### 1.3 真实 SSE 投递失败可见（`internal/api/stream.go`）

`http.Flusher.Flush` 没有错误返回值，旧 handler 忽略 flush 失败，于是“消费者已经不在”仍会被
上报为投递成功。改用 `http.NewResponseController(w).Flush()` 并把错误返回给 emit：投递失败的
帧现在是真正的消费者停止，统一驱动据此停止派发；已封存后的 final 投递失败由内容半边按
“成功不回滚”处理。

### 1.4 先红后绿复现的真实差异

流式路径过去固定用 `maxPhysicalAttempts+1` 作为 fallback 号，adapter 类可用性错误（不重试，
1 次主尝试）会留下 `[1,4]` 空洞；同步路径在 C2.01 已收敛为 `[1,2]`。红证据
`C2.02-red-pytest.txt`：同一真实栈用例在旧代码上 `assert [1, 4] == [1, 2]` 失败；`d8dfc23`
后通过，且帧序列、generation 与账本同时断言。
