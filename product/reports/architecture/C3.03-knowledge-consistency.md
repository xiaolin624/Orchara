## 1. 复现的泄漏与最小修正

### 1.1 场景（真实端点/真实行/真实字节）

### 1.3 根因与修正（`internal/knowledge/readable_chunk.go`）

根因有两面，缺一不可：

- 删除 A 的即时删除规则只 tombstone `source_artifact_id = A` 的文档；替换为 B 后文档行指向
  B，所以删除 A **不会** tombstone 该文档（这是正确的：B 是当前源，重建仍需合法完成）。
- 三路共用的 `currentReadableChunkSQL` 没有把 chunk 与其 **citation 中的来源 artifact**
  关联起来，因此“文档仍存活 + v1 仍是活动索引”使 A 派生 chunk 继续可读/可命中缓存。

修正只在**唯一共享谓词**增加一个 metadata join（不复制权限策略、不改三路调用者）：

```sql
JOIN platform.artifacts AS src
  ON src.id = CASE
       WHEN kc.citation->>'source_artifact_id'
            ~* '^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$'
       THEN (kc.citation->>'source_artifact_id')::uuid
     END
...
AND src.owner_id = kb.owner_id
AND src.deleted_at IS NULL AND src.state <> 'deleted'
```

- 这是“当前可读片段谓词”的即时删除事实，不是 revision 条件：**旧活动索引在其来源仍存活时
  继续可读**（重建中/失败后，§3 矩阵 #1/#2 显式断言），只有被删来源派生的 chunk 被拒绝；
  没有新增 `d.state='ready'`、最新 revision 或“活动索引必须最新”条件。
- CASE+正则先验证 UUID 形状再 cast，非法/缺失 citation 来源值不会让检索 SQL 报错，而是
  使该 chunk 不可读（fail closed）；metadata join 走 `artifacts` 主键，不新增对象打开。
- 修正自动覆盖全部读取者：`Query`/`QueryBases`（内部 retrieval 路由）、`GetChunk` 引用打开、
  `Answer` 逐引用复检、`cachedRetrieval → CheckCached` 缓存命中，因为四者都复用
  `currentReadableChunkSQL`（`grep currentReadableChunkSQL` 仅 `reader.go` 三处调用）。
- 未改 `cache_store.go` 的 keep/delete 决定：确定性拒绝（含来源删除导致的“当前不可读”）
  仍 `item_unreadable` 丢弃整条；瞬态仍 `cache_unavailable` 保留（§3 #6/#7）。

### 1.4 修正后同一场景（真实栈断言摘要）

`test_c303_deleting_the_old_source_while_the_replacement_builds_blocks_all_read_paths`：

- 删除 A 后：真实 body artifact 仍 `ready`、A 的封存对象仍在盘、chunk body 的 sha256/size
  与真实字节一致（证明阻断不是 purge/丢字节造成的）；检索 `items=[]`，cache
  `hit=false, discarded=true, discard_reason=item_unreadable`，且**同一 key**（文档行未动，
  `key_prefix` 不变）——命中复检而非换 key 拒绝；旧 cache 行被确定性删除；citation 404
  （不泄露 text/citation/object key）；回答 `no_results` 且无 citations。
- 随后放开真实排队重建：v2 `ready`、`activated_at` 非空，v1 `superseded`/`superseded_at`
  非空；旧 citation 全部 404；新检索只返回 B 的 chunk（`华南地区十一月…` 标记）、无 A 文本，
  citation 200，cache 重新 store → hit，answer `answered`。
- 同一用例内真实 cache-off 第二个 API 进程：检索/引用/回答与 cache-on 逐字段一致
  （空结果、404、`no_results`），且 off 进程不写缓存行。

## 5. 新增校验开销（记录，不作毫秒断言）

  的 owner/deleted/state），不新增对象 `Open`、不读取正文、不重复哈希。reader 的字节校验形状
  不变：每个候选恰好 1 次 open + 1 次有界 read + 1 次 SHA-256（C3.01 Go 单测锁定）；缺失/
  非法完整性 metadata 仍 0 次 open。
