## 新增测试与“为什么此前缺失”

| 覆盖 | 此前状态 | 本票补充 |
|---|---|---|
| CLI 真实退出码 × 每种来源/复制件新增修改删除 | 历史测试多经进程内 `sync.main()` 或 `check()`；仅进程中断用子进程 | `run_cli()` 子进程矩阵，断言 `returncode` 与逐条诊断 |
| 检查不修复复制件 | 历史只断言同步失败不替换复制件 | 成功/漂移/缺基线三态前后管理目录逐文件字节比较 |
| 来源不是目录 | 只覆盖来源缺失 | 真实文件占位来源路径 → `source_unavailable` 退出 1 |
| 基线缺失 | 只覆盖损坏基线 | 删除基线 → `missing_manifest`，且检查不重建 |
| 时间/绝对位置/提交号不决定内容 | 只间接覆盖 `_source_commit` 被 mock | 改写基线元数据 + 同内容换绝对来源位置，均退出 0 |
| 归一化/二进制经 CLI | 只在 module 入口覆盖 | CRLF 文本通过、不可解码二进制 CRLF 变化仍失败 |
| 同名运行契约经 CLI | 只在 module 入口覆盖 | 新增/合法同步/篡改三态均经 CLI |
| CLI 与 module 诊断一致 | 未显式比对 | 同一漂移的 findings 与 CLI 输出一致 |
