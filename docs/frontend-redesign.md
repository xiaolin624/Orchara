# Orchara 全产品前端改版

状态：用户已确认设计共识，全产品界面已实现并完成本轮 UI 验收。实现及验收证据见 `product/PROGRESS.md` 与 `product/reports/ui-redesign/README.md`（路径相对仓库根）。

跟踪任务：[GitHub #163](https://github.com/xiaolin624/Orchara/issues/163)。

## 已确认决定（2026-11-09）

- 覆盖整个产品的全部页面，验收范围不缩为首页、创作台或少量示范页。
- 用户对当前页面的评价是缺少完整的布局、样式、UI 设计、配色和图标。本次需要建立完整、一致的界面设计。
- 采用浅色专业工具风：灰白底色、克制的品牌色、清晰分区、适度留白；画布保留足够的信息密度。
- 沿用现有产品范围、业务术语与 Vue 3 / Vue Flow 决策。视觉设计确认不代表现有业务能力或实际验收通过。
- 普通页面采用左侧导航、顶部标题与操作区、主体内容区；编辑器采用节点库—画布—属性面板，并可收起导航。
- 登录后的默认落点为对话工作区，提供应用目录与创作台入口；技术状态归入管理入口。
- 常用操作、业务状态、必要提示直接展示，高级配置及内部 ID、原始 JSON、诊断日志按需展开。审批内容、数据去向和失败原因保留清晰展示。

## 已核对的实现事实

实际产品实现位于 `../product/`，其 `PROGRESS.md` 为实现进度权威。根级交接快照不代表当前产品未实现。

- 页面位于 `../product/apps/web/src/`，多数采用独立 HTML 和页面脚本，各页面样式分散。
- 公共导航源为 `../product/apps/web/src/assets/nav.js`，按用户角色显示入口。
- 画布源码位于 `../product/apps/web/canvas/src/`，构建产物位于页面的 `assets/canvas.js` 与 `assets/canvas.css`。
- 本次只读核查尚未启动页面进行视觉检查。

## 继续沿用的界面约束

依据 `../UX.md` 及既有 ADR：

- 对话、应用目录、创作台、个人数据、管理台的业务职责继续沿用；按角色显示适用入口。
- 普通业务人员通过画布与配置表单创作；桌面画布优先，手机支持对话、审批和查看结果。
- 草稿冲突、运行进度、取消、恢复、审批、删除等状态必须忠实反映服务端事实。
- 发布与审批所需的权限、内容、数据目的地及真实测试证据必须可见。
- 用途目录、我的应用及工作流画布使用既有术语，避免将应用与节点混用。

## 实现与验收约定

用户已对本轮全部问题确认。颜色数值、字号、间距和图标等可逆细节由实现统一确定，不再逐项访谈。出现新的领域术语或有实际权衡且难以逆转的决策时，再按领域文档约定记录。

全站共享设计变量、基础组件与页面外壳，保留现有业务脚本和服务端鉴权路径。页面截图、构建与回归分别留下证据；测试数据不冒充真实模型结果。桌面及支持的手机旅程检查布局、键盘焦点、可读性和主要操作，完整画布仍以桌面为目标。
